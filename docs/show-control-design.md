# 進行を自動で進める・ラッチ・予備機（設計）

2026-11 の点検（`docs/review-2026-11-19.md`）で出た新機能の案のうち、おすすめの 5 つを作る。
作る順は下の 1 → 5。1 つ終わるごとに `swift build` を通す。

## 共通の考え方

- **勝手に出すものは、必ず目に見える**。予約があるキューには「あと 0:12」「19:00:00 に」のような札を出し、「今」「次」の大きな表示にも残りを出す。
- **人の操作が先**。人が「次へ」「戻る」「飛ぶ」をしたら、前のキューが持っていた予約は消える（新しく出したキューの予約だけが生きる）。
- **止める手段がある**。キューのパネルに「自動で進める」の入切（`Engine.cueAutoEnabled`、保存しない・起動時はオン）。切ると、自動送り・時刻・0 での発火はどれも起きない（札は「止めている」と分かる見た目にする）。ブラックアウト中も進行は進める（裏で進んでいる方が、解いたときに合う）。
- 予約の判定は、**メインスレッドの 1 本のタイマー**（0.1 秒ごと。予約が 1 つも無いときは止める）で行う。描画スレッドから Engine を呼ばない。
- 時刻は 1 か所から取る：`ShowClock.now`（下の 4）。`Date()` を直接使っている時計のジェネレーターもここへ寄せる。
- 古いプロジェクトが読めること：足す項目はすべて Optional か、`init(from:)` を書かない struct なら既定値つきの Optional にする（Swift の自動の読み方は、既定値つきの非 Optional を「無いと失敗」にする。今の `Cue` の `fade` `keepOthers` と同じ形にそろえる）。
- 新しい版で作ったキューを古い版で開いても全体が読めなくならないように、enum に case を足さず、Optional の値で表す。

## 1. カウントダウンが 0 になったら次のキューへ

- 時計のジェネレーター（`.clock`）に値を 1 つ足す：「0 になったら」＝ 何もしない／次のキューへ。カウントダウンとタイマーのモードのときだけ出す。
  - 値の番号は今の並びの最後に足す（保存済みの値の並びをずらさない）。`EffectKind` の値の定義を読んで、足し方は今の決まりに合わせる。
- 判定は Engine 側（メインのタイマー）で：**出力で再生中**（`activeByLayer` に入っている。プレビューだけ・裏のデッキで再生していないものは数えない）の時計クリップについて、`ClockText.at(...).remaining` が「正 → 0 以下」に変わった 1 回だけ `fireNextCueAuto()`。
  - クリップごとに「前の残り」を覚える（`[UUID: Double]`、クリップの id）。出し直したら忘れる。
  - 同じ瞬間に 2 つの時計が 0 になっても、進むのは 1 回（同じタイマーの 1 回の見回りで 1 回まで）。
  - 起動したとき・出したときに既に 0 以下なら発火しない（「正だった」のを見てからだけ）。
- `fireNextCueAuto()`：`nextCue` があれば `fireCue`。`goGuard`（連打よけ）は見ないが、`lastGoHost` は更新する（直後の人の二度押しを防ぐ）。

## 2. キューの自動送り

`Cue` に足す：

```swift
/// このキューを出したあと、自動で次へ進む（nil = 進まない）
var follow: Follow?
struct Follow: Codable, Equatable {
    /// 秒数（after のとき）。nil = クリップが終わったら
    var after: Double?
}
```

- **○秒後に次へ**（`after` あり）：出してから `after` 秒で次へ。選択肢は 1・2・3・5・10・15・30・60 秒と「秒数を入れる」。
- **終わったら次へ**（`after == nil`）：クリップのキューだけ。そのクリップが **アウト点に着いたら** 次へ。
  - 「終わったら」がループ・往復のクリップでも、1 回目にアウト点へ着いた時に進む（ループは続いていてよい。次のキューが上書きする）。
  - 判定はタイマーで、再生位置から残りを見る（`ClipSlot` の今の位置・アウト点・速度を読む今ある手段を使う。無ければ足す）。残りが 1 コマ以下、または「最後で停止」で止まった状態になったら発火。
  - ジェネレーター・静止画・カメラなど終わりの無いものでは選べない（選べても何も起きない、ではなく、選択肢を出さない）。
- 予約は `Engine` に 1 つだけ持つ：`cueFollow: (cueID: UUID, fireAt: Double?)`。`fireCue` の最初で消し、出したキューに `follow` があれば入れ直す。キューを消した・並べ替えたら、id で見て無ければ消す。
- 見せ方：行の右のボタンの並び（今「終わったら」「フェード」がある所）に、自動送りのボタンを足す（アイコン `arrow.turn.down.right` など。設定があるときは青緑で「3秒」「終わり」）。「今」の大きな表示に「次へ あと 0:03」。

## 3. 時刻で発火

`Cue` に足す：

```swift
/// この時刻になったら自動で出す（その日の 時:分:秒。nil = なし）
var at: TimeOfDay?
struct TimeOfDay: Codable, Equatable { var h: Int; var m: Int; var s: Int }
```

- タイマーが、`ShowClock.now` の「今日の秒」が `at` を **またいだ**（前の見回りでは手前、今は過ぎた）ときに、そのキューを `fireCue`。順番は関係ない（何番目のキューでも、その時刻に出る）。
- 二重に出さない：またいだ判定は「前の見回りの時刻」と比べる。見回りの間が 5 秒より空いたとき（スリープから戻った・時計を大きく動かした）は、またいでも出さない。
- 起動したとき・プロジェクトを開いたときに既に過ぎている時刻は出さない。
- 見せ方：行に時計の札「19:00:00」と、1 時間以内なら「あと 12:30」。設定は行の右クリックと、行のボタンから（時・分・秒の 3 つの欄。「今から 1 分後」のボタンがあるとリハーサルで便利）。
- 日付は持たない（毎日その時刻）。プロジェクトを開いたままだと翌日も出るので、説明書に書く。

## 4. リハーサル用の時計ずらし

```swift
/// 進行で使う「今」。リハーサルのときだけ、本当の時刻からずらせる
enum ShowClock {
    /// ずらし（秒）。保存しない。0 = 本当の時刻
    static var offset: TimeInterval = 0
    static var now: Date { Date().addingTimeInterval(offset) }
}
```

- `TextGenerator.swift` で `Date(timeIntervalSinceNow: t - CACurrentMediaTime())` のように本当の時刻を作っている所は、ずらしを足す（描画スレッドから読むので、`offset` はロックか atomic な読み方に。今のコードの決まりに合わせる）。
- キューのパネルに「リハーサル：時刻を仮に決める」を置く（メニューかポップオーバー）：「今を 23:59:30 にする」＝ 入れた時刻になるように `offset` を決める。「本当の時刻に戻す」。
- ずらしている間は、キューのパネルと出力モニターに **黄色の帯「リハーサル中：時計 +3:12:05」** を出し続ける。保存しない。アプリを開き直すと 0。
- ずらしを変えた瞬間は、3 の「またいだ」判定を取り直す（変えた瞬間に過去の時刻のキューが出ないように）。

## 5. FX パッドのラッチ

`FXPad` に足す：`@Published var latch = false`（保存は `SavedPad` に `latch: Bool?`）。

- ラッチのパッドは、押すと入り、もう一度押すと切れる（離しても切れない）。アタック・リリースは今までどおり効く。
- キー・クリック・MIDI・OSC（`/halo/pad/N 1/0`）のどれでも同じ：「押した」で入切を切り替え、「離した」は無視。OSC は `1` で切り替えとし、`/halo/pad/N/latch 0/1` で入・切を直接決められるようにもする。
- 設定は、パッドの右クリックの今のメニュー（キー・アタック・リリースがある所）に「押している間だけ／押すたびに入切」。
- 見せ方：ラッチで入っているパッドは、押している間と同じ光り方のまま＋小さな錠の印。出力モニターの隅に、入っているラッチの名前を小さく出す（切り忘れに気づけるように。`OutputMonitor` の札の並びに）。
- Esc（ブラックアウト）・⇧Esc（全停止）では切れない。「全部のラッチを切る」を FX パッドの見出しの右クリックに置く。シーンを呼んでも切れない（パッドはシーンと別、という今の決まりのまま）。
- 今の `heldPads` / `releasingPads` の作りを読んで、押した・離したの入口（`pressPad` / `releasePad` に当たるもの）で分ける。描画への渡し方は変えない。

## 6. 予備機との同期

- **送る側**（今ある OSC の送り `OSCHub` の送信がオンのとき）：`fireCue` のたびに `/halo/cue/current N`（N は 1 から）を送る。ブラックアウトの入切で `/halo/blackout 0/1`。
- **追う側**：設定（OSC の所）に「予備機として追う」の入切（`@AppStorage`、既定は切）。入のとき、受けた `/halo/cue/current N` で `fireCue(N-1)`（今がもう N なら何もしない）、`/halo/blackout` でブラックアウトを合わせる。
  - 追う側は、自分の `/halo/cue/current` を送らない（2 台が送り合って止まらなくなるのを防ぐ）。
  - 追う側では、1〜3 の自動の発火は **しない**（本番機から来る番号だけで進む。両方が自分で進むと二重になる）。パネルに「予備機として追っている」の帯を出す。
- 今ある `/halo/cue/N`（人や外の機械からの命令）とは別のアドレスにする（意味が違う：命令ではなく「今ここにいる」の知らせ）。
- コマ単位の同期はしない（説明書に書く）。

## 試す（セルフテスト：新しいファイル `SelfTestShowControl.swift`、`SelfTest.swift` から呼ぶ）

`Engine(persistent: false)` で、時刻は関数に渡して試せる形にする（見回りの関数 `showTick(now: Date, host: Double)` を作り、タイマーはそれを呼ぶだけにする）。

- 0 で次へ：残りが正 → 0 以下で 1 回だけ進む／最初から 0 以下では進まない／出力していない時計では進まない／2 つ同時でも 1 回。
- 自動送り：○秒後に進む／人が先に「次へ」を押したら前の予約は消える／戻ったら消える／クリップの終わりで進む（テスト用の動画 `testclips/` を使う今のテストの書き方に合わせる）。
- 時刻：またいだら出る／既に過ぎていたら出ない／見回りが 5 秒以上空いたら出ない／ずらしを変えた瞬間は出ない。
- 「自動で進める」を切ると、どれも起きない。
- ラッチ：押す → 入る、離す → 入ったまま、もう一度押す → 切れる。ふつうのパッドは今までどおり。保存して読み直しても残る。
- 予備機：`/halo/cue/current 3` で 3 番目が出る／同じ番号は出し直さない／追う側は自動の発火をしない。
- 古い保存（`follow` `at` `latch` が無い JSON）が読める。
